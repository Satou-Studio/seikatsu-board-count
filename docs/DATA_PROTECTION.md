# 記録の保護と検証

更新日: 2026-09-08（実装・テスト実施日: 2026-09-07）

## 対象と目的

公開済みVersion 1.0の保存データを引き継ぎ、読み込み失敗や項目0件による自動上書きを防ぐ。
今回の実装は次回アップデート向け。App Storeへのアップロード・公開は行っていない。
設定画面・親ゲート・項目編集導線の追加、他アプリの変更は対象外。

## 読み込みの区別

| 保存状態 | 動作 |
| --- | --- |
| 保存キーが存在しない初回起動 | 見本5項目を1回保存 |
| 読み込める既存データ | 項目・記録をそのまま表示。読み込むだけでは保存し直さない |
| 正常な項目0件・記録0件 | 0件を維持。次回起動でも見本を作らない |
| 壊れたJSON、Data以外の値、非対応schema、未知フィールド、不整合な記録 | 原本を変更せず、通常画面に代えて説明と選択肢を表示 |

読み込み失敗中は、画面だけでなくStoreの追加・編集・削除・並び替え・記録追加・取消・保存も停止。
再読み込みが成功した場合のみ通常操作へ戻る。失敗中の再読み込みでキーが消えていても
初回扱いにはしない。

## 元データを残して再開する場合

1. 「もう一度読み込む」は元データを読み直すだけで、修復・初期化はしない。
2. 「空の状態から始める…」は確認ダイアログを開く。キャンセルでは何も保存しない。
3. 確認後、元のUserDefaults値を端末内のApplication Support/CountRecovery/
   配下の新しいUUID名のplistファイルへatomic保存し、読み戻したバイト列の一致を確認する。
4. 控えの保存・検証に失敗したら初期化せず、元データと操作停止を維持して理由を表示する。
5. 控えを保存できた場合のみ、元の保存キーを正常な0件状態にする。見本は入れない。
   過去の控えは削除・上書きせず、以後の通常操作も控えには触れない。

控えの構造はbinary property listの辞書で、`storageKey`と`originalValue`を持つ。
Dataの元バイト列だけでなく、想定外の文字列・配列・辞書なども元の型のまま保全する。
これは調査用の原本保全であり、記録の完全復旧を保証しない。アプリ内の控えからの
自動復元・取り込み機能はない。アプリを削除すると控えも消えるため削除しないことを案内する。
利用者の記録や控えはGit・テスト成果物へ入れず、外部送信しない。

## 保存互換性

- 保存キー: `seikatsuboard-count-state-v1` を維持。
- 項目ID、記録ID、項目との関連、日付キー、回数は維持。日付キーの再計算・変換はしない。
- Version 1.0のJSONルートは `items` / `records`。この旧形式を明示的に受け入れる。
- 今回はルートに整数 `schemaVersion: 1` を追加。旧形式の読み込みでは書き込まず、
  次の通常操作で同じ項目・記録構造にバージョンを付けて保存する。
- 未知のroot/item/recordフィールドや1以外のschemaを捨てて読み込むことはしない。
- 重複ID・同じ項目と日の重複レコード・参照先がない記録・負の回数・合計の整数超過などは、
  自動補正せず原本を保護する。
- 過去版バイナリへ戻した場合の保護は保証しない。旧版自体には失敗時の上書き処理が残る。

## 再現と回帰テスト

修正前の `bacf26b` 相当のStoreに4テストを追加して実行。初回見本のテストは成功し、
以下の3テストが失敗した。

- 壊れた13バイトのデータが519バイトの見本JSONへ置き換わった。
- 全項目削除後の再生成で0件を維持できなかった。
- 想定外の文字列の保存値が見本JSONへ置き換わった。

テストは独立したUserDefaults suiteと一時バックアップディレクトリを使用する。
UIテストは揮発性の起動引数で読み込み失敗を再現し、Simulatorの保存済み記録を破損させない。

実行方法:

```sh
xcodebuild test -project SeikatsuBoardCount.xcodeproj -scheme SeikatsuBoardCount \
  -destination 'platform=iOS Simulator,name=iPhone 17' -parallel-testing-enabled NO \
  -derivedDataPath /private/tmp/count-data-protection CODE_SIGNING_ALLOWED=NO
```

既存のアプリTarget・Scheme名は維持し、単体テストとUIテストのTargetを追加した。
追加した復旧案内だけString Catalogで管理する。既存画面全体の文言移行は行わない。

## 2026-09-08 実機への上書き更新

- 対象: iPhone 15 Pro / iOS 26.6.1。ソースは `e79a25f`。
- 既存の署名設定で実機向けDebugビルドに成功し、コード署名検証も成功。
  Bundle ID `com.saku.seikatsuboardcount`、Version 1.0 / Build 1を維持。
- 更新前の端末には開発用の旧版1.0 / Build 1が入っていた
  （端末情報の `builtByDeveloper: true`）。App Store版からの更新確認とは区別する。
- 更新前の保存値は旧形式で項目5件・記録0件。対象アプリの保存値だけをMacの一時領域へ控え、
  アンインストールせず上書きインストールと通常起動に成功した。
- 更新後の保存値は元バイト列と完全一致。項目・ID・並び順を保持し、読み込むだけでは
  schema付加や見本の再生成が起きないことを実機でも確認した。
- 実際の利用記録は0件だったため、過去記録ありの更新互換性は今回の実機では未確認。
  記録ありの互換性は前述の合成データによる単体テストの結果として扱う。
- 記録追加→アプリ終了・再起動後の回数保持→取消で元の回数へ戻る操作は、
  同日、利用者から「確認できた」と回答を受けた。
  実機VoiceOver、App Store配布版からの更新は引き続き未確認。
- 保存データの控えはGitに含めず外部送信していない。GitHubへのpush、App Storeへの
  アップロード・審査・公開は実行していない。
